    银行贷款项目

    广东华兴银行信用贷系统 (2023.11 - 2024.12) 项目介绍优化#

    面试官您好，接下来我介绍一下我负责的“广东华兴银行信用贷系统”这个项目。

    第一步：这个项目是干什么的，客户群体是谁？#

    （思路：用一两句话清晰概括项目背景、目标和用户，展现你的商业理解能力。）

    这个项目是为广东华兴银行打造的一套**全线上个人信用贷款平台**。它的核心目标是解决传统贷款申请流程繁琐、审批慢的问题，为广大有短期融资需求的个人客户提供一个**申请简便、审批快速、当天就能放款**的线上服务渠道。

    所以，我们的客户群体非常明确，主要分为两类：

    • 外部用户：有线上贷款需求的个人客户，他们希望通过手机App就能快速获得信贷额度。
    • 内部用户：银行的信贷审批、风险管理和客户服务人员，他们使用这个系统的后台来提高工作效率，控制风险。

    第二步：它有哪些核心模块？#

    （思路：展现你对系统整体架构的理解，并自然地引出自己负责的部分。）

    整个信用贷系统业务逻辑很长，可以拆分为几个核心的业务模块：

    1. 用户与账户模块：负责客户的注册、身份认证、银行卡绑定等。
    2. 额度申请与审批模块：这是核心模块之一，包括用户资料提交、调用第三方征信、行内风控模型审批、给出最终授信额度。
    3. 贷款申请与放款模块：用户在获得额度后，进行提现申请，系统会执行放款操作。
    4. 还款管理模块：支持用户主动还款、自动扣款、账单查询等。
    5. 逾期管理模块：这也是我**主要负责测试的模块**，当用户未按时还款时，系统会自动触发一系列逾期处理流程。
    6. 后台管理模块：供银行内部员工使用，进行客户管理、账务核对、报表生成等。

    我在这个项目中，主要负责的就是**逾期管理模块**的端到端测试工作。

    第三步：介绍一个你非常熟悉的功能（以你负责的“逾期管理”为例）#

    （思路：这是展现你技术深度和细节把控能力的关键！不要只说“我测了什么”，要说“这个功能是怎么工作的，我又是怎么从头到尾保证它的质量的”。）

    我重点介绍一下我负责的“逾期管理”功能。这个功能虽然是贷后环节，但直接关系到银行的资产安全，所以业务逻辑和数据处理的准确性要求非常高。它的核心交互流程是这样的：

    1. 状态自动触发：系统每天凌晨会有一个定时任务（Job），扫描所有贷款合同的应还款日。一旦发现有用户的还款日已过但未收到足额还款，系统会自动将该笔贷款的状态从“正常”更新为“逾期”。
    2. 罚息计算与记录：状态变更后，系统会**立即调用罚息计算接口**，根据逾期天数和预设的罚息利率，计算出当天的罚息金额，并准确记录到用户的账单中。
    3. 多渠道催收通知：同时，系统会触发通知服务，通过**App Push、短信**等方式，告知用户其贷款已逾期，并提醒尽快还款。
    4. 后台任务生成：在银行的内部后台，系统会为这笔逾期贷款生成一个催收任务，并根据逾期天数的长短，自动分配给相应级别的催收人员。

    在测试这个功能时，我的关注点非常细致：

    • 接口层面：我会用 JMeter 重点测试罚息计算接口。比如，构造不同逾期天数、不同本金、不同利率的请求参数，验证返回的罚息金额是否与预期（手动计算的结果）完全一致，精度到分。同时，我还会进行异常测试，比如传入空的参数，看接口是否能返回合理的错误码。
    • 功能层面：我会手动或通过自动化脚本，在测试环境修改服务器时间来模拟“逾期”场景，验证：
      • 贷款状态是否**准时、准确**地变更为“逾期”。
      • 用户端App收到的催收通知，其**文案、金额、跳转链接**是否正确。
      • 我会用 Fiddler 抓包，检查App在请求用户账单数据时，服务端返回的逾期状态和罚息金额是否正确无误。
      • 登录后台管理系统，验证催收任务是否已生成，并且分配的人员是否符合业务规则。
    • 数据层面：我会直接查询数据库，校验逾期记录表、账单表、罚息流水表等相关数据的一致性和准确性。

    通过这种“接口+功能+数据”的立体测试策略，我可以确保这个核心风控功能万无一失。

    第四步：你的测试流程是怎样的？#

    （思路：将你简历中的职责要点，按照标准的软件测试生命周期（STLC）串联起来，展现你的专业性和流程规范性。）

    在这个项目中，我严格遵循标准的测试流程来推进工作：

    1. 需求分析阶段：我会深度参与需求评审会议，不仅是听，更重要的是从测试角度**评估需求的可测性**，比如一些边界条件、异常场景是否明确，提前把模糊点暴露出来。
    2. 计划与设计阶段：我会使用 XMind 将负责模块的需求拆解成详细的测试点，形成一个思维导图。这既能保证测试的广度，也方便后续评审和编写用例。然后，我会基于测试点编写**具体的测试用例**，并组织开发、产品一起进行用例评审，确保大家对业务规则的理解是一致的。
    3. 测试执行阶段：
      • 接口测试先行：在UI界面还没开发好时，我就会用 JMeter 对后端接口进行测试，尽早发现底层逻辑问题。
      • 功能与UI测试：拿到测试包后，进行系统的功能测试。期间我会使用 Fiddler 进行抓包，辅助定位前后端bug，提高沟通效率。
      • 自动化测试：对于核心且稳定的功能，比如登录、贷款申请主流程等，我使用了 Python + Selenium + Pytest 框架编写了UI自动化脚本。这些脚本会通过 Jenkins 设置定时任务，比如每天凌晨自动执行一次，实现了无人值守的回归测试，极大地提升了效率。
    4. 缺陷管理：发现的bug会立即在JIRA上提交，我会详细描述复现步骤、附上截图或日志，并**持续跟进**，直到bug被修复、回归测试通过后才关闭。
    5. 总结报告：在项目上线前，我会输出一份详细的**测试报告**，内容包括测试范围、执行情况、缺陷分析、遗留风险和最终的上线建议，为决策提供数据支持。

    整个过程中，我非常注重**主动沟通**，定期与产品、开发同步测试进展和风险，确保信息透明，高效地推动问题解决。

    第五步：你对这个项目的总结，以及同行的优秀案例#

    （思路：展现你的思考和总结能力，以及对行业的洞察力，这是加分项。）

    项目总结：

    总的来说，这个项目对我而言是一个非常宝贵的经历。首先，它让我对复杂的金融业务，特别是信贷和风控领域有了非常深入的理解，这对于测试金融软件至关重要。其次，我在项目中将接口测试、UI自动化测试、CI/CD等技术和流程完整地实践了一遍，特别是将自动化测试有效地融入到了敏捷开发流程中，显著提升了测试效率和项目质量。

    行业洞察：

    谈到同类产品，目前市场上做得比较出色的，我认为有几个代表：

    • 蚂蚁集团的“借呗”：它的优势在于和支付宝生态的深度绑定，用户授权后几乎可以“秒速”出额度，用户体验做得非常极致。
    • 微众银行的“微粒贷”：它依托于微信和手机QQ两大社交平台，获客渠道非常强大，并且在风控模型上经过了海量用户的验证，非常成熟。
    • 招商银行的“闪电贷”：作为传统银行数字化转型的典范，它的优势在于合规性和稳定性，能给用户更强的安全感，并且与招行自身的零售业务结合得很好。

    我认为这些产品的共同点都是**以客户为中心，简化流程，并利用大数据和AI技术进行精准风控**。这也是我们项目持续优化的方向。

    最后给你的建议：

    • 自信：你做的这些工作内容非常扎实，技术栈也很主流。面试时一定要自信、流畅地表达出来。
    • 准备数据：如果可能，可以准备一些量化指标，比如“我负责的模块共发现有效bug约XX个，其中严重级别以上占XX%”、“自动化用例覆盖了XX个核心场景，将回归测试时间从X小时缩短到X分钟”，这会让你的描述更有说服力。
    • 练习：自己对着镜子或者找朋友模拟面试几次，把这套说辞讲熟练，变成你自己的话。

    希望这份优化对你有帮助！如果你还有其他问题，比如针对某个具体技术点的深入提问，或者想聊聊职场发展，随时都可以再问我。祝你面试顺利！
